# Generate the Xcode project from project.yml and keep signing identifiers out of Git

The Xcode project is generated by XcodeGen from `project.yml`. The generated `.xcodeproj` is not committed. The development team ID and the bundle identifier prefix are read from `JimakuApp/Signing.xcconfig.local`, which is gitignored; `JimakuApp/Signing.xcconfig` holds neutral defaults that work in the simulator.

Why: a committed `project.pbxproj` would carry one person's team ID and bundle identifier, so nobody else could sign the app without editing tracked files, and the owner's identifiers would be public. A generated project also avoids merge conflicts in a file nobody reads.

Rejected: committing the `.xcodeproj`. Rejected: Tuist, which does more than this project needs.

Cost accepted: XcodeGen must be installed, and `xcodegen generate` must be run after pulling changes to `project.yml`.
